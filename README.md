# HEBUT 图书馆预约与到馆助手

当前开发版 **1.3.0**，由官方页面油猴脚本、Cloudflare Worker 和一个 SQLite Durable Object 组成。计划可以在控制页随时修改；预约与签到结果以学校回执为准。

本版本已完成离线工程验证，**尚未部署、未完成本校真实预约与签到验收**。完整结果见 [测试矩阵](docs/TEST_MATRIX.md) 和 [外部核验](docs/EXTERNAL_VERIFICATION.md)。

## 普通用户使用

由维护者完成一次部署和学校规则核验后，打开其提供的 `https://<Worker 地址>/control`。管理令牌只在此独立控制页输入，不要在学校页面、控制台、URL 或油猴设置中输入。控制页仅在内存保存令牌，断开或刷新后需重新输入。

1. 连接后选择生效日期。首次迁移保持暂停、仅查询，保留原部署房间、座位和时段。
2. 填房间编号与座位 `216,215,217`；点击候选按钮可向前移动优先级。
3. 添加“全天 08:30–22:00”“下午 14:00–20:00”等模板，选默认模板；必要时添加某一天的模板覆盖。
4. 选择明天、指定日期或按星期循环，填写暂停日期。所有时段须符合学校已核验的房间规则；保存不代表规则已经核验。
5. 点击“预览配置差异”，确认生效日和变更，再保存。设置保存与预约提交是两个动作，不必重新部署。
6. 选择本次目标日期，点击“只读校验 / 模拟”。未开放、超出提前天数、时段网格错误、证据缺失都会给出阻断原因。
7. 在明确授权且所有门禁通过后，点击“执行一次预约”，或让已启用的计划按分钟 Cron 执行。只能在官方开放后的有限迟到窗口内自动运行；不保证毫秒级抢座。
8. 到馆点击“打开官方到馆流程”，本人完成学校要求的扫码、网络、定位或人工步骤，再回读官方签到状态。只有经核验学校记录为 `SIGNED_IN` 才显示已签到。

“候选优先级”仅在首选提交得到**经本校核验的明确座位冲突码**后，至少等待一分钟再尝试下一个。网络错误、429、验证码、失效登录、不明确成功都停止切换。缺少冲突契约时只尝试首选，不猜测文案。

“暂停所有预约”立即阻止后续提交，保留所有已发送请求与未知账本；它不会取消学校预约。已尝试的日期被冻结，换座或改时段只能先按学校正式流程处理；控制页修改未来生效日不会误删旧预约。

控制页打开且浏览器允许通知时，提供提前、临近提示截止两种到馆提醒。领取提醒在 DO 持久去重，两个标签页也只领取一次；浏览器关闭、刷新期间的通知不保证送达。默认 30/30 分钟偏移只是程序提示，不能当作校方窗口证明。

## 油猴安装与升级

使用 Node 24；仓库根目录运行：

```powershell
npm ci
npm run check
```

安装或更新 `dist/hebut-chaoxing-seat-helper.user.js`，在本人正常登录的官方选座页使用本地模拟和只读诊断。新安装模拟时段统一为 08:30–22:00，旧用户保存的 08:00 等偏好保持不变，请按真实规则核对。

**本版本自动写入统一归 Worker 协调。** 油猴没有持久远端提交授权，LIVE 会被拒绝；模拟流程不会调用 `vm.submit()`。升级时请先停用其他旧版本、其他标签页和旧预约脚本，避免它们独立写入。本地模拟设置与 Worker 计划独立，真实目标以 Worker 控制页预览为准。不要把长期管理令牌放进油猴或学校页面。

只读诊断默认关闭，开启后仅观察本人正常页面的 index/getstatus 响应。先预览脱敏结果再导出；缺少捕获时仅粘贴 Network 的 Response JSON，不能复制 Headers、Cookie 或 HAR。替代编号与日期绝不能用于真实请求。`seatengine` 页面当前支持诊断，原页面模拟适配器仍限已核验结构的 `seat` 选座页。

## 开发者与离线预览

```powershell
cd worker
npm ci --ignore-scripts
npm run check
node scripts/preview-control.mjs
```

先由 check 生成 `.build/index.js`，再打开 `http://127.0.0.1:18765/control`。本地预览令牌为公开合成值 `LOCAL_PREVIEW_ONLY`，它不属于任何生产账号。预览不加载 `.dev.vars`，关闭所有学校写入，拦截所有学校请求；退出进程即丢弃预览数据。它不能证明学校兼容或浏览器布局已验收。

项目没有新增依赖。Worker 类型检查、217 项单元与 8 项 workerd/SQLite 集成，根目录 75 项，共 300 项；见测试矩阵中的实际运行记录。依赖安装需要网络，测试本身使用离线合成数据。

## 故障处理与回滚

| 提示 | 处理 |
| --- | --- |
| `PLAN_REVISION_CONFLICT` | 重新连接读取最新计划，再编辑预览；不会覆盖另一页修改 |
| `EXISTING_ATTEMPT_FROZEN_USE_FUTURE_DAY` | 选择更晚生效日，旧预约在官方系统另行处理 |
| `SUBMITTED_UNVERIFIED` | 保留账本，等待回读或人工查看“我的预约”，不要重置/反复点击 |
| `OFFICIAL_RULES_UNVERIFIED` / `ELIGIBILITY_EVIDENCE_REQUIRED` | 保持模拟，由维护者按外部核验文档补证据 |
| `AUTH_EXPIRED` | 本人在官方系统重新登录；维护者在本地更新会话 secret，勿粘贴到聊天 |
| `RUN_BACKOFF` / `POLL_BACKOFF` | 等待显示的退避时间，避免连续查询 |
| 未收到到馆提醒 | 检查浏览器通知权限与控制页是否仍打开，按学校窗口自行到馆 |

学校人工流程始终可用。禁用油猴即可卸载页面功能；不要为了卸载而清空 DO 或未知提交账本。回滚先暂停写入，再按 [运维说明](worker/README.md) 回滚 Worker 代码，保持 DO 名称与身份不变。不要恢复旧版独立 LIVE 与新版 Worker 同时运行。
